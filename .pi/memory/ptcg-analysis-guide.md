# PTCG 卡牌/卡组分析手册（pi 专用）

> 用途：pi 对用户做 PTCG 单卡分析、卡组分析、组卡建议时，先读本手册再动手。
> 数据都在本项目内，无需联网。卡名/ID/效果一律以本地数据库为准，禁止凭记忆编造。

---

## 一、数据索引（数据在哪、格式是什么）

### 1. 卡牌数据（权威来源，读这些）

| 文件 | 路径 | 说明 |
|------|------|------|
| 索引 | `ptcg/data_fast/{type}.idx.tsv` | ID + 卡名，快速定位 |
| 数值 | `ptcg/data_fast/{type}.filter.tsv` | HP / 进化阶段 / 属性 / 撤退 / 弱点 |
| 招式 | `ptcg/data_fast/attacks.tsv` | 全类型招式，按 cardId 关联 |
| 特性 | `ptcg/data_fast/abilities.tsv` | 全类型特性，按 cardId 关联 |
| 详情 | `ptcg/data_fast/{type}.detail.tsv` | 描述/效果/弱点/画师/系列 |
| 搜索 | `ptcg/data_fast/{type}.search.tsv` | 预计算搜索文本（名字+英文+招式） |
| 系列 | `ptcg/data_fast/sets.tsv` | 卡包代码 ↔ 系列名 |

**{type} 取值**：`pokemon` / `supporter` / `item` / `pokemon-tool` / `stadium` / `basic-energy` / `special-energy`

### 2. 关键 TSV 列结构（解析时对照）

- `{type}.idx.tsv`：`ID \t 卡名 \t ...`
- `pokemon.filter.tsv`：`ID \t HP \t 进化阶段(0/1/2) \t 属性代码 \t 撤退 \t ? \t 弱点代码 \t ?`
- `attacks.tsv`：`cardId \t 系列代码 \t 编号 \t 招式序号 \t 招式名 \t 消耗 \t 伤害 \t 效果 \t ?`
- `abilities.tsv`：`cardId \t 系列代码 \t 编号 \t 特性序号 \t 特性名 \t 特性效果`
- `{type}.detail.tsv`：`ID \t 效果/描述文本 \t ...`（非宝可梦的 [1] 列是干净效果文本）
- `{type}.search.tsv`：`ID \t 搜索文本`（末尾含环境标记字母）

### 3. 卡牌 ID 规则（card_key）

- 格式：`{系列代码}-{编号}`，如 `CSV10C-151`、`151C-001`；旧数字 ID（如 `4521`）已废弃
- 前缀 `CSV` = 简中系列（CSV10C = 共逐荣光 I 标，CSV9C = 星彩晶璃 H 标）
- 环境标记：从 search.tsv 末尾字母读取，或从 ID 前缀数字推断 CSV10+→I、CSV7+→H、CSV4+→G

### 4. 属性代码映射

`G`=草 `R`=火 `W`=水 `L`=雷 `P`=超 `F`=斗 `D`=恶 `M`=钢 `Y`=妖 `N`=龙 `C`=无

### 5. 环境过滤规则（硬性）

- 当前标准环境：G/H/I 标（A-F 已退环境）
- 分析/组卡时只推荐 G/H/I 标的卡，退环境卡即使搜到也要排除

### 6. 知识库（战术知识，直接读）

| 文件 | 内容 |
|------|------|
| `ptcg/data/knowledge/techniques.md` | 对战技巧（先攻/后攻、奖赏卡、支援者时机、换位、伤指物、状态） |
| `ptcg/data/knowledge/deck-building.md` | 构筑理论（配比、能量数学、宝可梦线、自检清单） |
| `ptcg/data/knowledge/matchups.md` | 对局分析（主流卡组、克星、反制卡、换备） |
| `ptcg/data/knowledge/combos.md` | 强力组合（填能引擎、爆发、控制、回收、模板） |
| `ptcg/data/knowledge/rulings.md` | 规则 FAQ（进化、伤害、特性、能量、状态、ACE SPEC） |

### 7. 环境元数据

`ptcg/data/meta.json` — 上位卡组列表、ACE SPEC 清单、基本能量 ID、泛用卡。组卡组取基本能量 ID 时必须从这里读，不要编造。

### 8. 快捷查询脚本

`ptcg/tools/query_card.py` — 输入卡名或 ID，输出完整卡牌数据。用法：
```bash
python ptcg/tools/query_card.py "派帕的獒教父ex"   # 按卡名模糊搜索
python ptcg/tools/query_card.py CSV10C-151         # 按 ID 精确查
```

## 二、环境速查（当前 G/H/I 标）

### 1. 环境规则要点

- 标准赛制：G/H/I 标，A-F 已退环境
- ACE SPEC 每卡组限 1 张，共 29 种（18 物品 + 6 道具 + 3 特殊能量 + 2 竞技场）
- 常用 ACE：英雄斗篷（+100HP）、极限腰带（对 ex +50 伤）、伟大巨树（牌库进化）、不公印章（手牌干扰）、秘密箱（弃3搜4种各1）、遗赠能量（-1奖）
- 1 个伤害指示物 = 10 点伤害
- 奖赏卡：ex=2、V=2、VSTAR=2、VMAX=3

### 2. 环境主流 archetype（上位卡组）

| 卡组 | 类型 | 核心思路 |
|------|------|----------|
| 沙奈朵ex | 超/2阶 | 填能引擎 + 伤指物控制（拉鲁拉丝→奇鲁莉安→沙奈朵ex），使用率最高 |
| 喷火龙ex | 火/2阶 | 高火力，自爆轴 + 反击轴，HP330 极难 OHKO |
| 多龙巴鲁托ex | 龙/2阶 | 铺伤控制，招式向备战区放伤指物 |
| 猛雷鼓ex | 雷/基础 | 爆发型，克制恶喷和多龙 |
| 洛奇亚VSTAR | 多打手 | 始祖大鸟填能引擎，上位转化率前三 |
| 密勒顿ex | 雷/基础 | 最快拿奖速度（222 模式），压制沙奈朵 |
| 刺龙王ex | 水/2阶 | 水能打手群 |
| 钥圈儿控制 | 钢/基础 | 特性封锁控制 |

### 3. 沙奈朵ex 愿增猿 build（经典分析，来自 claude 记忆）

核心逻辑：早期拉鲁拉丝铺场 → 奇鲁莉安「洗练」弃牌抽牌 → 沙奈朵ex「精神拥抱」从弃牌区填超能并放伤指物 → 愿增猿（恶能量）把伤指物移到对手 → 吼叫尾/克雷色利亚/振翼发把伤指物转化为拿奖线。这是中后期资源 + 伤指物控制卡组，不是纯正面打手。

### 4. 常用泛用卡（组卡时优先考虑）

- 支援者：博士的研究、老大的指令、玛俐、奇树、派帕、暗码迷的解读、艾莉丝的斗志
- 物品：好友宝芬（HP≤70 基础）、巢穴球、高级球、厉害钓竿、夜间学院、反击捕捉器
- 道具：招式学习器 进化、招式学习器 退化、不服输头带
- 竞技场：崩塌的竞技场、伟大巨树

## 三、分析框架

### A. 单卡分析（七步法）

1. 识别角色：纯辅助（填能/检索引擎）→ 找受益打手；纯打手 → 找加速辅助；半辅半打 → 双向搜；系统核心 → 全维度搜
2. 提取机制关键词：弃牌区+能量→坟场填能；伤害指示物→缩放/转移；备战区→后排；牌库+选择→检索；能量需求→加速；特殊状态→状态卡
3. 算关键数值：伤害线（基础/触发/配道具后，对照环境 HP 阈值）；能量线（几回合贴满，有无加速）；奖品交换比；耐力（HP+道具+回复）
4. 找瓶颈：T1/T2 能做什么；每回合依赖什么；引擎被拆怎么办；关键卡 prized 怎么办
5. 多方向搜配合卡 + 评估：奖品效率（1奖小人 > 2奖ex > 3奖VMAX）、启动成本、进化需求、HP 阈值、环境适应
6. 环境对局：对照主流卡组胜率预判，是否被克制，是否需要针对卡
7. 诚实评估：小改动优先；结构性缺陷不掩饰；给竞技定位（T1竞技/娱乐偏强度/纯娱乐）

### B. 卡组分析（回答这几个问题）

1. 主力打手是谁，奖品路线怎么走
2. 前两回合如何 setup
3. 每回合如何贴能量
4. 奖品交换路线是否成立
5. 干扰/抓枪体系支撑什么
6. 资源如何回收
7. 针对哪些对局，2-4 个 flex 位怎么换
8. 结构自检：60 张、宝可梦 12-18、训练家 30-36、能量 8-12、抽滤≥8、检索≥8、回收≥2、换位≥2、ACE SPEC=1、进化链完整、能量类型自洽

### C. 组卡建议（构筑思路）

- 从关键卡/打法出发，给完整 60 张清单（宝可梦/训练家/能量配比）
- 解释核心 sequencing、对局/flex 位
- 标注赛制合法性假设和社区数据来源
- 环境 archetype 家族：沙奈朵ex、喷火龙ex、密勒顿、古代 box、洛奇亚VSTAR、太晶 box 等

## 四、用户偏好（组卡时必须遵守）

来自用户长期反馈（claude 记忆库）：

1. 朋友局友好，娱乐偏强度 —— 不要给纯竞技压迫性卡组
2. 避免压迫性纯控制 —— 除非用户明确要求，否则不组纯 control/lock
3. 实用不卡手优先 —— 宁可用稳定的次优卡，不用高上限但卡手的卡
4. 不强塞关键卡 —— 如果用户指定的关键卡会让卡组变差，要诚实指出，不硬凑
5. 卡名/ID 必须来自数据库 —— 搜不到就是不存在，禁止机翻、禁止凭记忆编卡名
6. 同名卡多版本要说明 —— 有多个变体时列出或询问，不静默选一个

## 五、防幻觉铁律

- 卡名、ID、效果文本一律来自本地 TSV/JSON 数据库
- 搜索不到 = 当前环境不存在，绝不编造
- 基本能量 ID 从 meta.json 读，不凭记忆
- 退环境卡（A-F 标）不推荐
- 伤害/HP/能量需求等数值以 filter.tsv/attacks.tsv 为准，不算错
